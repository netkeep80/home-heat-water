# Домашняя инженерная топология: язык и интерактивная схема, v0

**Задача:** [#26](https://github.com/netkeep80/home-heat-water/issues/26). Первичная реализация — маленькая модель сложных соединений с портами, сценарными состояниями и интерактивным статическим представлением. **Не является исполнительным планом** и не утверждает скрытую геометрию по фотографии.

## Выбор языка и границ

Каноническая топология — **JSON** (`model/photo-study.json`, JSON является допустимым подмножеством YAML 1.2). Не вводим вторую онтологию требований и не переносим предметную физику в RepoGuard. При появлении необходимости можно добавить синтаксис YAML как другое представление этой же объектной модели, без новой семантики.

- `nodes` — **стабильные ID компонентов**. `kind`, `name`, `ports`, `view` и источник `evidence`.
- `ports` — именованные порты с типом среды `heating_water`, `potable_water`, `electric`, `signal`.
- `links` — самостоятельные **именованные соединения** между точными портами. У трубы в будущем `inner_diameter_mm`, `length_m`, `elevation_change_m`; пока по фото эти параметры не подставляются.
- `junction` — истинный многосторонний тройник/коллектор, а не совпавшие на изображении линии.
- `valve` / `pump` / `strainer` — элемент внутри пути со своей семантикой, измерительным точкам соответствует `gauge`.
- `scenarios` — именованные состояния кранов, сравнимые в браузере.
- `checks` — структурные свойства (достижимость), которые в дальнейших версиях будут связаны с требованиями и физическими вычислениями.
- `view` задаёт только координаты визуализации, **не** высоту/длину гидравлического пути.
- `evidence` различает owner-reported, присутствующее на фото и гипотетическое соединение.

Соединение двух портов **не задаёт автоматически направление потока**. Замкнутые контуры не запрещены. Давление и расход требуют геометрии, характеристик арматуры/насоса и граничных условий. **Достижимость при открытом кране — только структурная, не физическое доказательство циркуляции.**

## Текущий прототип

`model/photo-study.json` содержит условную подсистему: граница ТА, тройник, основной кран, фильтр, ALPHA2, тройник с отводом манометра, возвратный тройник, альтернативный кран и обход. **Конкретные связи сделаны как демонстрация языка; не утверждается, что они соответствуют невидимой трассе труб на фото.** Это полностью самостоятельная гипотетическая модель, пригодная только для фальсификации семантики и UI.

`src/network.ts` выполняет независимую проверку ссылок на порты, среды, состояний кранов; графовый обход учитывает выбранные положения кранов. `tests/network.test.mjs` содержит позитивные и негативные проверки. Условный запас тепла использует **уже существующую** `storedHeatKWh` из `src/thermal.ts` и задаёт ΔT=40 К **как допущение, не измерение**.

## Pages

Статическое приложение (`site/`) предоставляет: схему, выбор компонента/связи, инспектор, переключение трёх сценариев, ручную изоляцию двух кранов, структурный `PASS/FAIL/UNKNOWN`, идеальную оценку запаса тепла, импорт изменённого JSON через текстовое поле и экспорт в локальный файл. Это **не** multi-user редактор, пользовательская модель **не** коммитится в GitHub.

Локальная сборка после `npm install`: `npm run build:pages` -> `public/`. Pages workflow `.github/workflows/pages.yml` запускается при обновлении `main` и вручную после включения **Settings → Pages → Build and deployment → GitHub Actions**. Источник GitHub Pages настроен на GitHub Actions по скриншоту владельца; до успешного развертывания статус сайта неизвестен. Не нужны сервер, API-токены или секреты.

## RepoGuard

RepoGuard v5.0.0 получает обычные `documents`, `implemented_by`, `verified_by` связи на файлы с точными путями. `SubjectRef` допускает durable JSON Pointer (например `/nodes/PUMP`, `/links/C08`), но **физические клапаны/трубы не нужно превращать в новые ядровые виды RepoGuard**.

## Следующие границы

1. Снять подтверждённую по факту исполнительную гидросхему, прежде всего реальные порты тройников, смешивающего клапана, хлопушек и расширительной части.
2. Добавить настоящий heat-exchanger с раздельными средами, управляемые трёхходовые клапаны, сигнал термореле дымохода, питание насосов от AES.
3. Только по известным паспортным кривым и геометрии ввести расходы, потери давления, естественную циркуляцию и приоритет ГВС.
4. Тогда же рассмотреть drag-and-drop схематический редактор вместо условной визуализации; доказать, что это оправдано реальными задачами.

**Никаких изменений реальной установки этот прототип не предписывает.**
