# Home Heat & Water — инженерные системы дома

Проект фактического обследования, расчётов и поэтапной модернизации **отопления, горячего и холодного водоснабжения** дома (~80 м²).

Связанный проект электроснабжения: [netkeep80/aes](https://github.com/netkeep80/aes). Электрическая архитектура принадлежит AES; здесь определяются нагрузки и требования со стороны отопления/водоснабжения.

## Состояние
**DISCOVERY / AS-IS.** Инженерные решения о закупке и монтаже не приняты. Отделяем наблюдаемые факты, гипотезы и решения владельца.

- Котёл Metal-Fach SMART MAXI 30, дрова; существующая открытая система.
- Самодельный ТА ~550 л из обычной стали ~3 мм, эксплуатируется около 6–7 лет.
- Установлены 3 × 2 кВт ТЭНа, обычно используются 2 × 2 кВт в окне 23:00–07:00.
- Бойлер косвенного нагрева ГВС 120 л заряжается естественной циркуляцией от ТА; производительности/ёмкости недостаточно, точная причина не установлена.
- Источник воды — собственная скважина; анализ именно её воды ещё необходим.

## Цели
- Максимально предсказуемая долговечность основных ТА, ориентир до 50 лет **как цель проектирования, не гарантия**.
- Замена расходных электрических нагревателей без опорожнения основных ёмкостей.
- Достаточные ГВС и холодное водоснабжение, выбор водоподготовки по измерениям.
- Прозрачный расчёт теплового запаса, электрических нагрузок и совместимости с AES.
- Сохранение аварийных защит и проверка монтажа профильными специалистами.

## Инженерные расчёты (TypeScript)
```bash
npm install
npm run typecheck
npm test
npm run scenarios
```
Модель — первоначальная аналитика, не гидравлический или прочностной расчёт. Зафиксированы допущения, расчёты покрыты предметными тестами.

## RepoGuard 4.x
Канонические проектные требования в `requirements/*.rg.yaml` с адресными `documents` / `implemented_by` / `verified_by` отношениями к реальным файлам. GitHub Actions использует **immutable pin** [RepoGuard v4.1.0](https://github.com/netkeep80/repo-guard/releases/tag/v4.1.0) (`6490ddc499ce01fa35b854dd4afbe0996d444165`). `repo-policy.json`, legacy service и внешнее разрешение изменений не используются. `repo-guard` проверяет причинную структуру файлов, но не заменяет предметные тесты или инженерную приёмку.
